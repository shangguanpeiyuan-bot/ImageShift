# ImageShift 产品规格

规格日期：2026-09-13。目标版本：1.0.0+1。

本文件整理用户最终完整产品需求，是长期产品目标，不是已完成功能清单。实施顺序以 [ROADMAP.md](ROADMAP.md) 为准；用户已在 A/B 后授权继续 C/D。实现证据见阶段报告，未验证的能力不得对用户宣称已支持。

## 1. 产品与项目身份

- 产品名称：ImageShift；Flutter project name：`imageshift`。
- Flutter organization：`io.github.shangguanpeiyuanbot`。
- Android Application ID：`io.github.shangguanpeiyuanbot.imageshift`。
- 工作目录：`D:\ImageShift`；现有分支：`main`。
- 仓库：<https://github.com/shangguanpeiyuan-bot/ImageShift.git>。
- 定位：快速、现代、完全本地、注重隐私的批量图片转换与常用图片处理软件。最终应达到普通用户可安装使用的正式软件完成度，不能仅交付 Demo 或 WebView 套壳。
- 双平台：Android 与 Windows；核心图片逻辑共享，文件访问和交互遵循各平台习惯。

## 2. 隐私与数据安全（不可放宽）

所有图片识别、解码、编辑、编码、缩略图、元数据和批处理均在本机完成。不上传用户图片，不调用在线图片转换服务或需要上传图片的云端 API；不加入广告、账户系统、服务器数据库或不必要的网络依赖。开发时下载依赖不等于应用处理图片需要联网。

不删除原图，不覆盖原图，不扫描无关用户目录，不收集图片内容。首页及关于页明确说明“所有图片处理均在本地完成，不会上传至服务器”。历史只保留任务摘要，不能保存图片本体。日志避免记录用户图片、敏感元数据或凭据。

所有变换仅对解码副本处理，输出为新文件。v1.0.0 不提供覆盖原文件功能。重名策略为自动编号或跳过，默认自动编号；已有输出文件也不能被悄悄替换。

## 3. 优先级

| 级别 | 内容 |
| --- | --- |
| P0 | 格式转换、批量转换、质量、尺寸、输出管理、真实格式检测、队列、错误隔离、取消、Android/Windows 文件选择、Windows 拖拽、Android Release APK、Windows Release Build |
| P1 | 图片压缩、裁剪、旋转、翻转、元数据查看与清理、批量重命名、预设、历史、主题、转换前后对比 |
| P2 | Windows 文件夹导入、可靠的剪贴板图片、快捷键、系统通知、高级预览交互 |

稳定性、数据安全和 P0 优先。P2 依赖不稳定时暂缓，不能因此破坏 Android / Windows Release Build。流水线、持久化、完整 UI 和发布交付按四阶段计划逐步验收。

## 4. 格式能力与真实性

优先研究 JPG/JPEG、PNG、WebP、BMP、GIF、TIFF、TGA、ICO。每种格式必须分别记录：依赖宣称的解码能力、依赖宣称的编码能力、项目已实现能力、项目测试证据、平台实测情况及限制。可以读取不代表可以写出。不能只依据包的名称、扩展名或记忆判断能力。

新增依赖前核实当前稳定版本、维护情况、许可证（含附属版权声明）、API、Android 与 Windows 支持和格式子类型。输出选项必须由经过验证的编码能力生成；禁止没有真实编码器的按钮、无效参数和“伪 WebP”。HEIC/HEIF、AVIF、RAW、PSD 暂不强制，仅在双平台可靠且风险可控时增加。

识别应使用文件头、magic bytes、结构校验与实际解码结果。扩展名仅用于文件名提示；PNG 内容即使名为 `photo.jpg` 也应识别为 PNG。TGA 等弱签名格式必须结合结构和解码验证，不能以任何随机二进制猜测成功。受损的已知格式应报损坏/解码错误，不能当成功转换。

动画 GIF、APNG、WebP、多页 TIFF、ICO 多图像需要明确策略：仅当完整保存帧/页/时序得到验证时才宣称保留。仅保留首帧必须事先提示“转换后将变为静态图片”；尚无确认机制时拒绝该输入，禁止静默丢帧。

## 5. 转换、质量与压缩

- 单图与批量格式转换共享核心服务。Phase A 至少完成 PNG → JPG、JPG → PNG、BMP → PNG；若确认编码库支持 WebP，则增加 PNG → WebP 和对应测试。
- JPG 质量 1–100，默认 90。不支持透明；透明输入默认与白色背景合成，后续支持黑色及自定义背景。不能留下随机颜色或黑边。
- PNG 保持 Alpha，不因转换无故丢失透明度。
- WebP lossy/lossless 选择及质量参数只在实际编码器支持时开放；仅无损编码时明确标记无损，不能展示有损质量滑块。
- 独立图片压缩工具支持保持格式压缩或转格式压缩，参数随格式变化。输出后读取真实大小，显示原大小、输出大小、减少/增加的字节和百分比，不保证每张图片一定变小，不将估算值冒充结果。

## 6. 尺寸及几何工具

尺寸调整默认关闭，保持宽高比默认开启。提供原尺寸、25%/50%/75%、自定义；高级支持固定宽、固定高、最长边、最短边；预设包括 1920×1080、1280×720、1080×1080、1080×1920、2560×1440、3840×2160。提供禁止放大开关，启用后任一输出维度不能超过对应输入维度。

Phase A 明确语义：指定宽高且保持比例时以该宽高为边界框等比缩放；不保持比例时使用目标宽高；禁止放大优先于放大请求。非法、非正数或超出资源限制的尺寸必须拒绝。

后续裁剪支持自由裁剪与 1:1、4:3、3:4、16:9、9:16、3:2、2:3，支持拖动、调整、重置，输出前不修改源文件。旋转支持顺时针/逆时针 90°、180°，翻转支持水平/垂直，具备实时预览。这些交互不属于 Phase A。

## 7. EXIF、Orientation 与元数据

优先保证手机照片视觉方向正确：处理 Orientation 的旋转及镜像，避免重复应用方向或写出错误方向标签。完整保留 EXIF 未验证前禁止宣称支持。

图片信息只展示实际解析到的格式、大小、宽高、Alpha、EXIF、方向、拍摄时间和相机信息；缺失字段不生成假数据。清理元数据必须创建新文件，并明确实际能清理的 EXIF、ICC、文本等类型及不能处理的内容。不能把重新编码自动等同于完整隐私清理。

## 8. 导入与文件列表

- Windows：单选/多选文件、拖拽导入；拖入区域高亮并提示“松开以添加图片”，不支持项跳过并给汇总提示。
- Android：使用当前官方文件访问机制，妥善处理 URI、目录授权与保存流程，不申请不必要的全盘权限，不硬编码无权限目录。用户取消选择属于正常结果。
- 导入后展示缩略图、文件名、真实格式、宽高、文件大小、状态。
- 列表支持选择/多选/全选、移除/清空、继续添加；可靠时支持拖动排序。大量文件支持搜索文件名、状态过滤（全部/等待/转换中/成功/失败）、动态格式过滤，按名称/大小/分辨率/格式升降序排序。
- P2 文件夹导入可选递归子目录，仅导入实际支持图片；普通 txt/exe/zip 不得导致整批中止。
- P2 剪贴板仅在可靠识别 Windows 图片数据时加入任务；无图片不报错，不稳定 Native 实现应暂缓。

## 9. 输出、命名与流水线

Windows 支持输出目录选择；Android 采用合法文件访问/保存机制。不能强制用户使用开发机上的路径。

默认保留文件主名并替换扩展名；冲突依次产生 `photo.jpg`、`photo_1.jpg`、`photo_2.jpg`。既不能覆盖源文件，也不能覆盖其他已存在文件；同一进程并发处理必须避免重名竞争。取消或失败的临时输出应可安全清理，不能留下伪装成成功的半文件。

批量重命名支持原名、前缀、后缀、顺序编号、起始编号和编号位数；提供原名 → 新名实时预览，例如 `ImageShift_0001`。

批处理流水线可组合尺寸 → 裁剪 → 旋转 → 格式转换 → 压缩 → 清理元数据 → 重命名；步骤可单独开关，顺序明确，避免重复有损编码。保存的参数必须能够还原真实执行计划。

## 10. 队列、取消与结果

队列状态：等待、处理中、成功、失败、已取消。防止重复点击启动重复任务。单文件失败隔离，损坏一张不影响其他文件。取消后未开始任务停止，已成功输出保留；当前不可中断的编码步骤不得假报立即取消，必须明确取消边界并安全结束。

批处理进度显示当前文件、完成数/总数、整体进度、耗时；无精确编码进度 API 时使用当前文件处理中和完成计数，不伪造单图百分比。

结果页展示成功/失败/取消数、真实耗时、输入与输出总大小及增减比例；支持打开输出位置、查看/重试失败项、再次转换及返回首页。Android 目录授权失效时需重新授权，不能保留无效操作。任务模型在 Phase A 建立，完整批量队列与取消在 Phase B 验收。

## 11. 预览与转换对比

正式预览器支持适应窗口、100%、缩放、拖动画布；Windows 鼠标滚轮/Ctrl+滚轮，Android 双指缩放。转换前后展示原图与结果及真实格式、尺寸和文件大小。结果变大时如实显示增加。

缩略图降采样并限制缓存，不能长期缓存全部原图解码数据。高级预览交互以性能稳定为前提。

## 12. UI 与双平台体验

采用 Material 3 建立统一颜色、字体、间距、圆角、阴影、边框和图标规范，不在 Widget 随意散布硬编码颜色。风格现代、简洁、轻量、清晰、克制；可用细边框、微弱渐变和柔和层次，避免霓虹、夸张玻璃、过度圆角及长动画。不能以默认 Flutter 计数器或按钮/表单堆砌充当最终产品。

Windows 使用 Sidebar/NavigationRail：首页、格式转换、批量处理、图片工具、历史、设置、关于，底部显示真实产品名及版本。大窗口多栏、普通双栏、窄窗口收缩，无 overflow、遮挡或文本重叠。Android 使用底部 NavigationBar：首页、工具、历史、设置；手机单列，大屏可双栏，适配横竖屏、返回键、触摸、DPI。

首页显示品牌、副标题“快速、安全的本地图片处理工具”、本地隐私声明、导入卡片。Windows 提示拖入，Android 提示选择。快捷工具统一图标/标题/说明，包括转换、批量、压缩、尺寸、裁剪、旋转翻转、图片信息、元数据清理。未实现入口不得伪装成可用功能。

加载、空、成功、失败、处理中、无历史均须中文友好文案和适当图标、说明、动作。Windows Hover、Tooltip，Android Pressed feedback；合理触摸面积；成功/失败不能仅用颜色区分。动画短且克制。

无现成品牌图标时创建原创简洁的“图像框 + 转换箭头”，验证版权并配置 Android Launcher 与 Windows 图标。首次启动可有简短本地/批量/隐私欢迎页及“开始使用”，状态持久化。

## 13. 主题、设置、历史与预设

浅色、深色、跟随系统均覆盖双平台；即时切换、持久化。设置包含默认输出格式、JPG 质量、实际支持的 WebP 参数、输出位置、命名、重名策略、自动打开目录、完成通知、记住参数。平台不支持或未实现的设置不展示为有效选项。

历史存储时间、任务类型、数量、成功/失败数量、格式、输出位置和可重用参数；不保存图片本体。支持查看、复用参数、打开目录、清空，尊重 Android 持续访问权限。

内置网页优化/高清 JPG/高质量 WebP/1080p/4K 等预设须映射实际能力；自定义预设支持保存、改名、删除、应用并持久化。使用轻量可靠的本地存储，无服务器数据库。

关于页从真实项目版本读取名称和版本，包含简介、隐私、仓库链接、项目许可证和主要开源依赖许可证。项目许可证需要明确确定，不能把依赖许可证冒充项目授权。

## 14. 快捷键

后续 Windows 支持 Ctrl+O 选择、Ctrl+Shift+O 文件夹（功能就绪时）、Ctrl+A 全选、Delete 移除、Ctrl+Enter 开始、Esc 关闭弹层/取消选择。Ctrl+V 仅在可靠剪贴板功能存在时启用。不能抢占 TextField 内正常 Ctrl+A/Delete/Ctrl+V 等编辑快捷键。

## 15. 架构、性能与错误

业务逻辑和 UI 分離；`main.dart` 仅承担启动。独立格式识别、解码、编码、转换、命名、任务、错误等核心模块，后续逐步增加平台导入/输出、队列、设置、历史、预设和 UI 状态。状态管理方案引入前核实当前维护及 API，避免过度架构。

图片 CPU 工作放入 Isolate/compute/后台任务，控制并发，避免 UI isolate 长时间编解码、一次解码几十张大图或原图长期驻留。定义输入字节、像素及输出资源限制；头部尺寸检查优先于完整解码；不能宣称软件限制能够完全杜绝 OOM。后续用 4K、8K、手机高像素、大 TIFF、大批次实测耗时与内存，记录硬件和数据规模。

错误覆盖不存在、损坏、非法文件、解码/编码失败、不支持格式、后缀不符、读权限、写权限、目录不可写、空间不足、大图资源限制、重名和取消。主提示中文、明确、可读，技术异常仅留调试信息，不把原始 Dart Exception 直接当用户提示。

## 16. 测试与验收原则

程序生成 RGB/RGBA、不同尺寸、透明和损坏测试素材，禁止下载版权未知素材。转换测试必须检查真实输出存在、可重新解码、真实格式和宽高，不允许只断言返回 true。

Phase A：PNG → JPG、JPG → PNG、BMP → PNG；WebP 编码支持则测试 PNG → WebP；白底透明合成、尺寸、等比、禁止放大、自动编号、原图保护、损坏/非法输入、真实识别、读写失败。实际执行 `flutter pub get`、`flutter analyze`、`flutter test`，修复范围内错误并记录真实输出。

后续补充单文件失败隔离、取消、队列防重复、流水线顺序、命名、设置/预设/历史持久化，以及动画/多页、EXIF、元数据边界。UI 除分析和 Widget 测试，还要实际启动 Windows 验证窄/普通/最大窗口、列表、滚动、弹窗、预览、参数面板、明暗主题；Android 尽可能用设备/模拟器验证手机纵横布局，缺少模拟器不能伪称设备测试通过，也不应阻塞 APK 构建。

## 17. 构建、安装与发布（Phase D 目标，尚未完成）

实际执行 `flutter build apk --release`，用日志与文件确认 APK。最终发布副本命名 `ImageShift-v1.0.0-Android.apk`，不删除原 APK；签名配置、密钥保管必须单独核实，调试签名不得宣称为正式发行签名。

实际执行 `flutter build windows --release`，确认 exe 和全部运行时依赖，不能只拷贝 exe 宣称完整便携版。使用经查询验证的成熟安装器方案，生成 `ImageShift-v1.0.0-Windows-Setup.exe` 或如实命名 MSI，包含名称/版本、开始菜单、卸载、可选桌面快捷方式；安装后不依赖 Flutter SDK。

README 应覆盖简介、实际功能、平台、分别验证的输入/输出格式、批量/流水线、工具、隐私、安装、源码构建、技术栈、结构、License 和已知限制。未完成功能只能写成计划。

Phase D 发布前检查 Git 内容，排除 build、local.properties、SDK 本地路径、IDE 缓存、临时文件、token、key、密码、.env、keystore/.jks。使用现有 main/origin，禁止 force push。完成最终验收后按用户发布要求提交、push，创建 v1.0.0 / ImageShift v1.0.0 GitHub Release，上传真实 APK 和安装器，说明功能、双平台、隐私和限制。授权失败只在该步骤暂停，保留本地成果。当前 Phase A 不提交发布、push、tag 或创建 Release。

## 18. 证据与工作约束

禁止伪造功能、格式支持、测试、构建、APK、Installer、GitHub 发布结果。以实际文件、命令输出、文档和错误为依据；失败后据实修复，不把未来目标写成完成。阶段状态集中维护在 ROADMAP，验收证据写入阶段报告。遇到必须人工 UAC、登录、授权、许可证确认或重启时，说明当前窗口与操作，处理后续接；常规已授权操作直接完成。
